# 部署与账号说明

本文档用于让不依赖 Codex 的同学或老师也能独立完成部署，包含：

- Windows 本地开发
- 本地 Docker 部署
- Ubuntu VM / Linux 服务器部署
- 阿里云 ECS 部署
- GitHub Actions 自动部署
- 环境变量、更新、回滚、备份、排障

## 1. 项目架构

项目由三个主要部分组成：

```text
frontend/   Vue 3 + Vite + Element Plus，生产环境由 Nginx 提供静态页面
backend/    FastAPI + SQLAlchemy，提供 API、判题、AI 反馈、考试接口
MySQL       MySQL 8.0，保存账号、题库、提交、考试、成绩等数据
```

默认生产部署方式是 Docker Compose：

```text
浏览器
  -> frontend 容器（Nginx，端口默认 8080/8081）
       -> /api/ 和 /uploads/ 反代到 backend 容器
            -> MySQL 容器
            -> Docker 沙箱执行代码（可选）
```

## 2. 两套 `.env` 的区别

项目存在两个不同用途的 `.env`，不要搞混：

| 文件 | 用途 | 谁读取 |
|---|---|---|
| `backend/.env` | 本地直接运行后端时使用 | `backend/app/config.py` |
| 根目录 `.env` | Docker Compose 启动时使用 | `docker-compose.yml` 和容器 |

模板文件：

```text
.env.example                               本地/开发模板
deploy/ubuntu/.env.production.example      生产/服务器模板
```

本地直接跑后端：

```powershell
Copy-Item ..\.env.example .env
```

注意这个命令在 `backend` 目录下执行，生成 `backend/.env`。

Docker Compose 部署：

```powershell
Copy-Item .env.example .env
```

在项目根目录执行，生成根目录 `.env`。

## 3. 环境变量说明

### 3.1 数据库

```dotenv
MYSQL_ROOT_PASSWORD=请改成强密码
MYSQL_DATABASE=coding_platform
DATABASE_URL=mysql+pymysql://root:请改成强密码@mysql:3306/coding_platform
```

注意：

- Docker Compose 内部，MySQL 服务名是 `mysql`。
- 容器之间通过 `mysql:3306` 访问，不要写 `127.0.0.1`。
- `DATABASE_URL` 中的密码必须和 `MYSQL_ROOT_PASSWORD` 一致。

本地直接运行后端时，默认使用 SQLite，不需要 MySQL：

```dotenv
DATABASE_URL=sqlite:///./coding_platform.db
```

### 3.2 端口

```dotenv
MYSQL_PORT=3306
BACKEND_PORT=8000
FRONTEND_PORT=8080
```

如果服务器上已经有其他项目占用端口，可以改：

```dotenv
MYSQL_PORT=13306
BACKEND_PORT=18000
FRONTEND_PORT=8081
```

注意：

- 前端端口是学生/老师访问的入口。
- 后端端口和 MySQL 端口默认只绑定 `127.0.0.1`，不建议直接暴露到公网。
- 修改端口后，访问地址也要对应修改。

### 3.3 账号与初始化

```dotenv
SECRET_KEY=请改成随机长字符串
TEACHER_REGISTER_CODE=请改成教师注册授权码
SEED_DEMO_ACCOUNTS=false
```

`SEED_DEMO_ACCOUNTS` 说明：

- `true`：空数据库启动时自动创建 `student / student123` 和 `teacher / teacher123`。
- `false`：不自动创建演示账号，适合交付学生。
- 生产模板默认 `false`，Docker Compose 默认也是 `false`。

### 3.4 AI 配置

```dotenv
AI_PROVIDER=local
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-v4-flash
QWEN_API_KEY=
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3.7-plus
```

`AI_PROVIDER=local` 时只使用本地规则反馈，不需要外部 Key。

### 3.5 代码执行沙箱

```dotenv
EXECUTION_MODE=docker
EXECUTION_TIMEOUT=5
CPP_EXECUTION_TIMEOUT=15
PYTHON_RUNNER_IMAGE=python:3.12-slim
NODE_RUNNER_IMAGE=node:20-alpine
JAVA_RUNNER_IMAGE=openjdk:17-jdk-slim
CPP_RUNNER_IMAGE=gcc:13-bookworm
```

生产环境建议：

- `EXECUTION_MODE=docker`
- 提前拉取 Python、Node、Java、C++ 沙箱镜像
- 不要给容器挂载宿主机完整根目录

## 5. 本地 Docker 部署

本地 Docker 部署适合模拟生产环境。

### 5.1 安装 Docker Desktop

安装 Docker Desktop 并启动，然后确认：

```powershell
docker --version
docker compose version
```

### 5.2 准备根目录 `.env`

```powershell
cd "D:\振涛教育\学生考试\理论判卷神器\coding-platform"
Copy-Item .env.example .env
```

编辑 `.env`，至少修改：

```dotenv
MYSQL_ROOT_PASSWORD=你的本地数据库密码
DATABASE_URL=mysql+pymysql://root:你的本地数据库密码@mysql:3306/coding_platform
SECRET_KEY=你的本地随机密钥
TEACHER_REGISTER_CODE=teacher2026
SEED_DEMO_ACCOUNTS=true
EXECUTION_MODE=docker
```

### 5.3 启动

```powershell
docker compose up -d --build
```

查看状态：

```powershell
docker compose ps
```

访问：

```text
http://localhost:8080
```

首次启动会自动创建数据库表并写入演示账号。

### 5.4 常用命令

```powershell
docker compose logs -f backend
docker compose logs -f frontend
docker compose restart backend
docker compose down
docker compose up -d
```

注意：

- `docker compose down` 不会删除 MySQL 数据。
- `docker compose down -v` 会删除 MySQL 数据卷，生产环境不要随便执行。

## 6. Ubuntu VM / Linux 服务器部署

以下步骤适用于 Ubuntu 22.04/24.04 或类似 Linux 环境。

### 6.1 准备服务器

创建普通用户并加入 `sudo` 组，或者使用已有用户。

检查端口：

```bash
sudo apt update
sudo apt install -y curl git
```

### 6.2 上传项目

Windows 上传整个项目：

```powershell
scp -r "D:\振涛教育\学生考试\理论判卷神器\coding-platform" ubuntu@服务器IP:~/coding-platform
```

如果使用 Git：

```bash
cd ~
git clone git@github.com:makainame/online-coding-platform.git coding-platform
cd coding-platform
```

### 6.3 安装 Docker

```bash
cd ~/coding-platform
bash deploy/ubuntu/setup_ubuntu.sh
```

脚本会安装：

- Docker CE
- Docker Compose 插件
- Buildx

安装完成后重新登录或新开 SSH：

```bash
exit
```

再重新连接，然后确认：

```bash
docker --version
docker compose version
```

### 6.4 配置 `.env`

```bash
cd ~/coding-platform
cp deploy/ubuntu/.env.production.example .env
nano .env
```

生产模板示例：

```dotenv
MYSQL_ROOT_PASSWORD=replace-with-strong-password
MYSQL_DATABASE=coding_platform
DATABASE_URL=mysql+pymysql://root:replace-with-strong-password@mysql:3306/coding_platform
SECRET_KEY=replace-with-long-random-secret
TEACHER_REGISTER_CODE=replace-with-teacher-register-code
SEED_DEMO_ACCOUNTS=false

MYSQL_PORT=13306
BACKEND_PORT=18000
FRONTEND_PORT=8081

AI_PROVIDER=local
EXECUTION_MODE=docker
CPP_EXECUTION_TIMEOUT=15
PYTHON_RUNNER_IMAGE=python:3.12-slim
NODE_RUNNER_IMAGE=node:20-alpine
JAVA_RUNNER_IMAGE=openjdk:17-jdk-slim
CPP_RUNNER_IMAGE=gcc:13-bookworm
```

生成随机密钥：

```bash
openssl rand -hex 32
```

把输出填入 `SECRET_KEY`。

### 6.5 提前拉取镜像

建议先拉取沙箱镜像，避免判题时临时下载超时：

```bash

docker pull python:3.12-slim
docker pull node:20-alpine
docker pull openjdk:17-jdk-slim
docker pull gcc:13-bookworm
```

### 6.6 构建并启动

```bash
cd ~/coding-platform
bash deploy/ubuntu/deploy.sh
```

或者手动执行：

```bash
docker compose up -d --build
```

查看状态：

```bash
docker compose ps
```

预期三个服务都处于 `Up` 或 `healthy`：

```text
coding-platform-mysql-1
coding-platform-backend-1
coding-platform-frontend-1
```

### 6.7 验证

服务器本机验证前端：

```bash
curl -I http://127.0.0.1:8081
```

验证后端 API：

```bash
curl http://127.0.0.1:18000/
```

局域网/公网访问：

```text
http://服务器IP:8081
```

### 6.8 创建正式教师账号

因为 `SEED_DEMO_ACCOUNTS=false`，首次启动不会创建演示账号。

打开前端页面，点击“注册”，选择“教师”，填写 `TEACHER_REGISTER_CODE`，创建正式教师账号。

## 7. 阿里云 ECS 手动部署

### 7.1 购买与初始化

推荐配置：

- 2 核 vCPU
- 4 GiB 内存
- 40 GiB 系统盘
- Ubuntu 22.04/24.04

### 7.2 安全组开放端口

在阿里云控制台找到 ECS 实例的“安全组”，添加入方向规则：

| 端口 | 用途 |
|---|---|
| 22 | SSH |
| 8081 | 前端访问，可改成你自己的 `FRONTEND_PORT` |

后端 `18000` 和 MySQL `13306` 默认只监听 `127.0.0.1`，不建议开放公网。

### 7.3 登录 ECS

Windows PowerShell：

```powershell

```

或者：

```powershell
ssh -i "C:\Users\你的用户名\.ssh\id_ed25519" ubuntu@123.56.244.128
```

### 7.4 上传项目

如果 ECS 上已经有目录，也可以先删除旧目录再上传。

### 7.5 安装 Docker

退出 SSH 再重新登录，使 Docker 权限生效。

### 7.6 配置生产环境

## 8. GitHub Actions 自动部署到阿里云

项目已经配置好自动部署工作流：

```text
.github/workflows/deploy-production.yml
```

触发方式：

- 推送或合并到 `production` 分支
- 在 GitHub Actions 页面手动运行

### 8.1 配置 GitHub Secrets

打开 GitHub 仓库：

```text
Settings
  -> Secrets and variables
    -> Actions
      -> New repository secret
```

需要添加：

| Secret | 示例 |
|---|---|
| `ECS_HOST` | `123.56.244.128` |
| `ECS_USER` | `root` |
| `ECS_SSH_KEY` | ECS 登录私钥内容 |
| `ECS_PORT` | `22` |

### 8.2 ECS 首次手动准备

自动部署不会覆盖 ECS 上的 `.env`，因为工作流排除了 `.env`。

所以第一次必须手动完成：

```bash
cd /root/coding-platform
cp deploy/ubuntu/.env.production.example .env
nano .env
```

后续每次推送 `production`，GitHub Actions 会：

1. 同步项目文件到 `/root/coding-platform/`
2. 跳过 `.git`、`node_modules`、`dist`、`logs`、`.env`、数据库文件
3. 执行 `bash deploy/ubuntu/deploy.sh`

### 8.3 查看部署结果

GitHub 仓库：

```text
Actions
  -> Deploy Production
  -> 最新一次运行
```

出现绿色 `success` 即部署成功。

### 8.4 手动触发部署

```text
Actions
  -> Deploy Production
  -> Run workflow
  -> 选择 production
  -> Run workflow
```

## 11. 数据库备份与恢复

### 11.1 备份

```bash
cd ~/coding-platform
mkdir -p backups
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" coding_platform' > "backups/coding_platform_$(date +%F_%H%M%S).sql"
```

### 11.2 恢复

```bash
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" coding_platform' < backups/你的备份文件.sql
```

### 11.3 自动备份

可以在服务器 crontab 中添加：

```bash
crontab -e
```

每天凌晨 3 点备份：

```cron
0 3 * * * cd /root/coding-platform && docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" coding_platform' > /root/coding-platform/backups/coding_platform_$(date +\%F).sql
```

## 13. 交付学生前检查

交付前建议按顺序完成：

1. 正式教师账号已创建。
2. 删除或重置 `student` 演示账号。
3. 删除或重置 `teacher` 演示账号。
4. `SEED_DEMO_ACCOUNTS=false`。
5. `TEACHER_REGISTER_CODE` 已改成自己的授权码。
6. `SECRET_KEY` 已改成随机长字符串。
7. `MYSQL_ROOT_PASSWORD` 已改成强密码。
8. 已完成数据库备份。
9. 已确认前端、后端、MySQL 均正常运行。

## 14. 常见问题

### 14.1 PowerShell 提示 npm 无法执行

```text
npm.ps1 无法加载
```

使用：

```powershell
npm.cmd run dev
npm.cmd run build
```

### 14.2 端口被占用

查看占用：

```powershell
netstat -ano | findstr :8080
```

或修改 `.env`：

```dotenv
FRONTEND_PORT=8081
BACKEND_PORT=18000
MYSQL_PORT=13306
```

### 14.3 后端 502

```bash
docker compose ps
docker compose logs --tail=80 backend
```

常见原因：

- MySQL 未健康
- 后端容器崩溃
- 前端容器里的旧 Nginx 缓存了旧后端 IP

处理：

```bash
docker compose up -d --build frontend backend
docker compose restart frontend
```

### 14.4 MySQL 无法连接

```bash
docker compose ps
docker compose logs --tail=80 mysql
```

常见原因：

- `DATABASE_URL` 中的密码与 `MYSQL_ROOT_PASSWORD` 不一致
- MySQL 数据卷损坏
- 服务没有启动

### 14.5 Docker Hub 拉取失败

配置国内镜像：

```bash
echo '{"registry-mirrors":["https://docker.m.daocloud.io","https://docker.1ms.run","https://docker.xuanyuan.me"]}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker
```

### 14.6 缺少 cryptography

```bash
docker compose build --no-cache backend
docker compose up -d backend
```

### 14.7 C++ 判题超时

先确认镜像已拉取：

```bash
docker pull gcc:13-bookworm
```

如仍超时，可调大：

```dotenv
CPP_EXECUTION_TIMEOUT=20
```

### 14.8 演示账号重新出现

确认：

```dotenv
SEED_DEMO_ACCOUNTS=false
```

然后重建后端：

```bash
docker compose up -d --build backend
```
