# 部署与账号说明

本文档用于让不依赖 Codex 的同学或老师也能独立完成部署，包含：

- Windows 日常开发（启动前后端查看效果）
- Linux 本地 Docker 部署（本地部署）
- Ubuntu VM / Linux 服务器部署（本地部署）
- 阿里云 ECS 部署
- GitHub Actions 自动部署
- 环境变量、更新、回滚、备份、排障

## 部署方式速查

先看下面这张表，确认你现在要做哪一种部署：

| 你的目标 | 算不算部署 | 使用哪套环境 | 看哪一章 |
|---|---|---|---|
| Windows 日常开发 | 不是部署 | Windows + Python + Node | 第 4 章 |
| Linux 本机/虚拟机 Docker 部署 | 本地部署 | Linux + Xftp + Xshell | 第 5、6 章 |
| 阿里云 ECS 线上部署 | 线上部署 | Xftp + Xshell + 阿里云控制台 | 第 7 章 |
| GitHub Actions 自动部署 ECS | 线上部署 | GitHub + GitHub Actions | 第 8 章 |

一句话判断：

- Windows 只启动前后端：看第 4 章，这不是部署。
- Linux 本机或虚拟机 Docker Compose：看第 5、6 章，这是本地部署。
- 阿里云 ECS：看第 7、8 章，这是线上部署。
- 想以后少手动操作：先手动部署一次，再配置 GitHub Actions。

## 账号体系

### 内置账号

- 教师/管理员：`teacher` / `teacher123`
- 演示学生：`student` / `student123`

### 公开注册规则

- 注册学生：必须填写自己的 AI API Key
- 注册教师：必须填写教师授权码
- 教师授权码由服务器环境变量 `TEACHER_REGISTER_CODE` 控制
- 开发环境默认授权码：`teacher2026`
- 生产环境必须在 `.env` 中改成自己的授权码

### AI Key 和练习数据

- AI Key 加密保存到学生账号下，跟随账号走
- 换电脑登录同一个账号，Key 不需要重新配置
- 提交记录、判题结果、AI 反馈、学习统计都保存在 MySQL，跨设备可见
- 编辑器草稿会自动保存，登录后进入题目可恢复上次未提交代码；点击“运行/提交”会额外保存提交记录

## 1. 项目架构

项目由三个主要部分组成：

```text
frontend/   Vue 3 + Vite + Element Plus，生产环境由 Nginx 提供静态页面
backend/    FastAPI + SQLAlchemy，提供 API、判题、AI 反馈、考试接口
MySQL       MySQL 8.0，保存账号、题库、提交、考试、成绩等数据
```

默认生产部署方式是 Docker Compose：

```text
浏览器
  -> frontend 容器（Nginx，端口默认 8080/8081）
       -> /api/ 和 /uploads/ 反代到 backend 容器
            -> MySQL 容器
            -> Docker 沙箱执行代码（可选）
```

## 2. 两套 `.env` 的区别

项目存在两个不同用途的 `.env`，不要搞混：

| 文件 | 用途 | 谁读取 |
|---|---|---|
| `backend/.env` | 本地直接运行后端时使用 | `backend/app/config.py` |
| 根目录 `.env` | Docker Compose 启动时使用 | `docker-compose.yml` 和容器 |

模板文件：

```text
.env.example                               本地/开发模板
deploy/ubuntu/.env.production.example      生产/服务器模板
```

本地直接跑后端：

```powershell
Copy-Item ..\.env.example .env
```

注意这个命令在 `backend` 目录下执行，生成 `backend/.env`。

Docker Compose 部署：

```powershell
Copy-Item .env.example .env
```

在项目根目录执行，生成根目录 `.env`。

## 3. 环境变量说明

### 3.1 数据库

```dotenv
MYSQL_ROOT_PASSWORD=请改成强密码
MYSQL_DATABASE=coding_platform
DATABASE_URL=mysql+pymysql://root:请改成强密码@mysql:3306/coding_platform
```

注意：

- Docker Compose 内部，MySQL 服务名是 `mysql`。
- 容器之间通过 `mysql:3306` 访问，不要写 `127.0.0.1`。
- `DATABASE_URL` 中的密码必须和 `MYSQL_ROOT_PASSWORD` 一致。

本地直接运行后端时，默认使用 SQLite，不需要 MySQL：

```dotenv
DATABASE_URL=sqlite:///./coding_platform.db
```

### 3.2 端口

```dotenv
MYSQL_PORT=3306
BACKEND_PORT=8000
FRONTEND_PORT=8080
```

如果服务器上已经有其他项目占用端口，可以改：

```dotenv
MYSQL_PORT=13306
BACKEND_PORT=18000
FRONTEND_PORT=8081
```

注意：

- 前端端口是学生/老师访问的入口。
- 后端端口和 MySQL 端口默认只绑定 `127.0.0.1`，不建议直接暴露到公网。
- 修改端口后，访问地址也要对应修改。

### 3.3 账号与初始化

```dotenv
SECRET_KEY=请改成随机长字符串
TEACHER_REGISTER_CODE=请改成教师注册授权码
SEED_DEMO_ACCOUNTS=false
```

`SEED_DEMO_ACCOUNTS` 说明：

- `true`：空数据库启动时自动创建 `student / student123` 和 `teacher / teacher123`。
- `false`：不自动创建演示账号，适合交付学生。
- 生产模板默认 `false`，Docker Compose 默认也是 `false`。

### 3.4 AI 配置

```dotenv
AI_PROVIDER=local
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-v4-flash
QWEN_API_KEY=
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen3.7-plus
```

`AI_PROVIDER=local` 时只使用本地规则反馈，不需要外部 Key。

### 3.5 代码执行沙箱

```dotenv
EXECUTION_MODE=docker
EXECUTION_TIMEOUT=5
CPP_EXECUTION_TIMEOUT=15
PYTHON_RUNNER_IMAGE=python:3.12-slim
NODE_RUNNER_IMAGE=node:20-alpine
JAVA_RUNNER_IMAGE=openjdk:17-jdk-slim
CPP_RUNNER_IMAGE=gcc:13-bookworm
```

生产环境建议：

- `EXECUTION_MODE=docker`
- 提前拉取 Python、Node、Java、C++ 沙箱镜像
- 不要给容器挂载宿主机完整根目录

## 7. 阿里云 ECS 手动部署（线上部署）

### 7.1 购买与初始化

推荐配置：

- 2 核 vCPU
- 4 GiB 内存
- 40 GiB 系统盘
- Ubuntu 22.04/24.04

### 7.2 安全组开放端口

在阿里云控制台找到 ECS 实例的“安全组”，添加入方向规则：

| 端口 | 用途 |
|---|---|
| 22 | SSH |
| 8081 | 前端访问，可改成你自己的 `FRONTEND_PORT` |

后端 `18000` 和 MySQL `13306` 默认只监听 `127.0.0.1`，不建议开放公网。

### 7.3 登录 ECS

在 Windows PowerShell 执行：

```powershell
ssh root@123.56.244.128
```

或者：

在 Windows PowerShell 执行：

```powershell
ssh -i "C:\Users\小泰迪\.ssh\id_ed25519" ubuntu@123.56.244.128
```

### 7.4 上传项目

#### 方式一：Xftp 上传（推荐）

Xftp 是用来把本地文件传到阿里云 ECS 的工具，Xshell 只负责连接后执行命令。

1. 打开 Xftp。
2. 新建连接，主机填：


```powershell
docker compose exec mysql mysql -uroot -p123456 -e "SHOW DATABASES;"
```

```powershell
docker compose exec mysql mysql -uroot -p123456 -e "CREATE DATABASE coding_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

处理步骤：

1. 启动 Docker Desktop，等待右下角 Docker 图标变稳定。
2. 在项目根目录确认 `.env`：

```dotenv
MYSQL_PORT=3307

```

3. 在 Windows PowerShell 执行：

```powershell
cd "D:\振涛教育\学生考试\理论判卷神器\coding-platform"

```

4. 确认 MySQL 容器是 `Up` 或 `healthy`。
5. Navicat 连接：

| 项目 | 值 |
|---|---|
| 主机 | `127.0.0.1` |
| 端口 | `3307` |
| 用户名 | `root` |
| 密码 | `123456` |

`TcpTestSucceeded` 必须为 `True`。

### 14.11 Navicat 报 1045：Access denied for user

1045 表示 SSH 隧道已经通了，但 MySQL 的用户名或密码不正确。

处理步骤：

1. 在 Xshell 登录阿里云：

```bash
cd /root/coding-platform
grep MYSQL_ROOT_PASSWORD .env
```

2. 复制冒号后面的完整密码，不要带空格。
3. 在 Navicat `常规` 标签页填写：

| 项目 | 值 |
|---|---|
| 主机 | `127.0.0.1` |
| 端口 | `13306` |
| 用户名 | `root` |
| 密码 | `.env` 中 `MYSQL_ROOT_PASSWORD` 的完整值 |
| 数据库 | `coding_platform` |

4. 点击“测试连接”。

不要填本地 MySQL 的 `123456`，除非阿里云 `.env` 里正好也是 `123456`。

如果确认密码正确，可以在 Xshell 测试：

```bash
cd /root/coding-platform
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SELECT 1;"'
```

能返回 `1`，说明 `.env` 密码正确，Navicat 里要复制同一串密码。

如果报错是：

```text
1045 - Access denied for user 'root'@'172.18.0.1'
```

说明 MySQL 容器里 `root` 没有允许从 Docker 网关连接。

在 Xshell 执行授权：

```bash
cd /root/coding-platform
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "CREATE USER IF NOT EXISTS \"root\"@\"%\" IDENTIFIED BY \"$MYSQL_ROOT_PASSWORD\"; GRANT ALL PRIVILEGES ON *.* TO \"root\"@\"%\" WITH GRANT OPTION; FLUSH PRIVILEGES;"'
```

授权后，在 Navicat 重新点“测试连接”。

注意：阿里云 MySQL 端口只映射到 `127.0.0.1`，所以这个授权只会在 SSH 隧道下可用，不会直接暴露公网。

## 15. 后续建议

- 正式域名和 HTTPS 可后续通过服务器 Nginx/Caddy 配置。
- 当前项目内 Nginx 只负责前端静态文件和反向代理，不包含 TLS。
- 如需多节点或更严格的资源隔离，可以继续优化 Docker 沙箱参数。
